# Merge lists

Два отсортированных односвязных списка объединяются в один. Функции принимают головы списков и возвращают голову результата. Пустой список обозначается `None`. Узел `Node` хранит значение `value` и ссылку `next`.

Входные списки должны быть отсортированы по неубыванию, не содержать циклов и общих узлов. Обе функции меняют связи между исходными узлами: значения не копируются, все узлы результата взяты из входных списков. После слияния исходные списки нельзя считать независимыми.

## Идея решения

На каждом шаге сравниваются первые ещё не обработанные узлы двух списков. Узел с меньшим значением добавляется в конец результата, а соответствующий входной указатель передвигается дальше. При равных значениях выбирается узел первого списка. Указатель `tail` хранит последний выбранный узел.

Выбранная часть результата всегда отсортирована: минимальный из двух текущих узлов не больше любого оставшегося значения, потому что оба входных списка уже отсортированы. На каждом шаге выбирается ровно один узел. Когда один список заканчивается, весь остаток второго присоединяется одной ссылкой: он уже отсортирован. Поэтому результат содержит все исходные узлы в правильном порядке.

### С фиктивным элементом

`merge_with_dummy` создаёт начальный узел `dummy`. Сначала `tail` указывает на него, поэтому даже первый настоящий узел можно добавлять обычным присваиванием `tail.next`. В конце возвращается `dummy.next`; сам фиктивный узел в результат не входит.

### Без фиктивного элемента

`merge_without_dummy` сначала обрабатывает пустые списки. Затем отдельно выбирает первый узел результата и сохраняет его в `head`. Дальнейшее слияние устроено так же, как в первом варианте, но новых узлов не создаётся.

## Пример

Исходные списки: `1 → 2 → 4` и `1 → 3 → 4`. В таблице показана уже выбранная часть результата; её последний узел хранится в `tail`.

| Шаг | Первый необработанный узел list1 | Первый необработанный узел list2 | Действие | Выбранная часть |
| --- | --- | --- | --- | --- |
| 1 | 1 | 1 | Взять из list1 | 1 |
| 2 | 2 | 1 | Взять из list2 | 1 → 1 |
| 3 | 2 | 3 | Взять из list1 | 1 → 1 → 2 |
| 4 | 4 | 3 | Взять из list2 | 1 → 1 → 2 → 3 |
| 5 | 4 | 4 | Взять из list1 | 1 → 1 → 2 → 3 → 4 |
| 6 | — | 4 | Присоединить остаток list2 | 1 → 1 → 2 → 3 → 4 → 4 |

В варианте без фиктивного элемента первый шаг выполняется до цикла и задаёт `head`. В варианте с фиктивным элементом он выполняется внутри цикла, а первый настоящий узел доступен через `dummy.next`.

## Сложность

Пусть длины списков равны `n` и `m`. У обоих вариантов время работы в худшем случае — **O(n + m)**: каждый шаг продвигает один из указателей, повторного обхода нет. Остаток списка присоединяется за **O(1)**.

Дополнительная память — **O(1)**: используются только несколько ссылок, а в первом варианте ещё один фиктивный узел. Узлы входных списков не пересоздаются, рекурсия не используется.

## Тесты

Тесты проверяют оба способа: пустые списки, одиночные узлы, пример из условия, чередующиеся и непересекающиеся диапазоны, повторы, отрицательные значения, разную длину и длинные списки. В каждом случае проверяются порядок значений, отсутствие циклов и точное совпадение набора узлов с исходным. Для каждого запуска создаются новые входные списки, поскольку слияние меняет связи.

Запуск из корня репозитория:

```bash
python3 -B -m unittest discover -s homework_2/merge_lists -v
```
