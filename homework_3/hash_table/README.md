# Создание хеш-таблицы

## Идея решения

`HashTable` хранит список корзин. Каждая корзина — список пар, а каждая пара — список `[ключ, значение]`. В реализации нет `dict` или `set`: все контейнеры, в которых хранятся элементы таблицы, имеют тип `list`.

Номер корзины вычисляется как `hash(key) % количество_корзин`. Ключ должен быть хешируемым; его хеш и поведение при сравнении не должны изменяться, пока он находится в таблице. Для равных ключей должны совпадать хеши. Значением может быть любой объект, в том числе `None` или список.

Коллизии разрешаются методом цепочек: разные ключи с одним номером корзины находятся в одном списке. Поэтому одного совпадения хеша недостаточно — внутри корзины сравниваются сами ключи. Тот же самый объект ключа также считается найденным.

- `insert(key, value)` ищет ключ в корзине. Если он есть, меняет значение; иначе добавляет новую пару и увеличивает размер.
- `search(key)` возвращает найденное значение. Отсутствие ключа обозначается `KeyError`, поэтому его можно отличить от сохранённого `None`.
- `delete(key)` удаляет найденную пару, уменьшает размер и возвращает её значение. Если ключа нет, выбрасывает `KeyError`.
- `len(table)` возвращает число пар, а не число корзин.

Перед добавлением нового ключа проверяется заполнение. Если число пар после вставки превысит 75% числа корзин, количество корзин удваивается. Все старые пары распределяются заново: остаток от деления на новое число корзин мог измениться. При обновлении существующего ключа размер и число корзин не меняются. После удаления таблица не сжимается.

Каждый ключ хранится ровно один раз в корзине с нужным индексом. Поиск и удаление проверяют всю эту корзину, поэтому находят ключ даже при коллизии. Удвоение сохраняет все пары и заново вычисляет их правильные индексы.

## Пошаговый пример

Начнём с четырёх корзин. Для небольших положительных целых чисел в этом примере `hash(k) = k`, поэтому ключи `1`, `5`, `9` и `13` сначала попадают в корзину `1`.

| Шаг | Операция | Корзины после операции | Число пар / корзин | Результат |
| --- | --- | --- | --- | --- |
| 0 | Создать таблицу | Все пусты | 0 / 4 | — |
| 1 | `insert(1, "A")` | `1: [[1, "A"]]` | 1 / 4 | — |
| 2 | `insert(5, "B")` | `1: [[1, "A"], [5, "B"]]` | 2 / 4 | Коллизия, новая пара в той же цепочке |
| 3 | `insert(9, "C")` | `1: [[1, "A"], [5, "B"], [9, "C"]]` | 3 / 4 | — |
| 4 | `insert(5, "B2")` | `1: [[1, "A"], [5, "B2"], [9, "C"]]` | 3 / 4 | Обновление, размер не растёт |
| 5 | `insert(13, "D")` | `1: [[1, "A"], [9, "C"]]`; `5: [[5, "B2"], [13, "D"]]` | 4 / 8 | Перед вставкой удвоение: `4 > 4 × 0.75` |
| 6 | `search(9)` | Без изменений | 4 / 8 | В корзине 1 пропустить ключ 1, вернуть `"C"` |
| 7 | `delete(1)` | `1: [[9, "C"]]`; `5: [[5, "B2"], [13, "D"]]` | 3 / 8 | Вернуть `"A"`; ключ 9 по-прежнему доступен |
| 8 | `search(1)` | Без изменений | 3 / 8 | `KeyError` |

Пустые корзины в таблице не показаны.

## Сложность

Пусть `n` — число пар, `m` — число корзин, `L` — длина нужной цепочки. В оценках считаем вычисление хеша и сравнение ключей операциями **O(1)**; для длинных строк или пользовательских объектов нужно дополнительно учитывать их стоимость.

| Операция | Ожидаемое время при равномерном распределении | Худший случай |
| --- | --- | --- |
| Поиск | **O(1)** | **O(n)**, все ключи в одной цепочке |
| Удаление | **O(1)** | **O(n)**, поиск и сдвиг элементов списка |
| Вставка / обновление | **O(1)** амортизированно для вставок | **O(n + m)** для одной вставки с расширением; без расширения **O(n)** |
| `len(table)` | **O(1)** | **O(1)** |

При равномерном распределении средняя длина цепочки равна `n / m` и ограничена порогом заполнения. Это не гарантия: увеличение таблицы не разделит ключи с одинаковыми хешами.

Одно расширение требует **O(n + m)** времени: создаются новые корзины и переносится каждая пара. При последовательных вставках размеры таблицы растут геометрически, поэтому суммарная стоимость расширений линейна по числу вставок, что даёт амортизированную оценку. Создание таблицы с начальным числом корзин `m₀` отдельно требует **O(m₀)** времени и памяти.

Память структуры — **O(n + m)** для корзин, пар и ссылок на ключи и значения; сами пользовательские объекты не копируются. При расширении временно нужны ещё **O(n + m)** памяти под новые корзины и ссылки. Остальные операции требуют **O(1)** дополнительной памяти без учёта роста контейнеров при вставке. После массового удаления `m` не уменьшается, поэтому память нельзя всегда оценивать как O(n) от текущего числа элементов. Рекурсии нет.

## Тесты

Проверяются вставка, обновление, поиск и удаление; отсутствующие ключи; значения `None` и пустой список; отрицательные и разные типы ключей; равные ключи; коллизии; удаление начала, середины и конца цепочки; расширение и повторное использование. Последовательности операций сравниваются с обычным словарём Python, который используется только в тестах как эталон.

Запуск из корня репозитория:

```bash
python3 -B -m unittest discover -s homework_3/hash_table -v
```
