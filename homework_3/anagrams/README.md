# Anagrams

Функция `group_anagrams(words)` возвращает список групп анаграмм. Входной
список не изменяется, повторяющиеся слова остаются в ответе. Группы идут в
порядке первого появления, слова внутри них — во входном порядке. Условие
не требует определённого порядка, поэтому такой ответ допустим.

## Идея решения

У анаграмм одинаковый результат сортировки символов: для `eat`, `tea` и `ate`
это строка `aet`. Используем её как ключ словаря `groups`, а значением храним
список исходных слов. Для каждого слова вычисляем ключ, при необходимости
создаём группу и добавляем в неё слово. В конце возвращаем все группы.

Регистр и все символы учитываются буквально. Например, `ab` и `aB` попадают
в разные группы. Ограничения на алфавит не добавляем; Unicode-нормализацию
и удаление пробелов не выполняем.

Две отсортированные строки равны тогда и только тогда, когда совпадают
символы и число вхождений каждого из них. Поэтому ключ объединяет ровно
анаграммы. После обработки первых `i` слов словарь содержит каждое из них
ровно один раз в правильной группе. На следующем шаге добавляется только
очередное слово, и это свойство сохраняется. Цикл проходит конечный список,
поэтому после его завершения все слова сгруппированы правильно. Коллизии
хешей словарь разрешает сравнением самих ключей.

## Пример по шагам

Вход: `["eat", "tea", "tan", "ate", "nat", "bat"]`.

| Шаг | Слово | Ключ | Словарь после добавления |
| --- | --- | --- | --- |
| 1 | `eat` | `aet` | `aet: [eat]` |
| 2 | `tea` | `aet` | `aet: [eat, tea]` |
| 3 | `tan` | `ant` | `aet: [eat, tea]; ant: [tan]` |
| 4 | `ate` | `aet` | `aet: [eat, tea, ate]; ant: [tan]` |
| 5 | `nat` | `ant` | `aet: [eat, tea, ate]; ant: [tan, nat]` |
| 6 | `bat` | `abt` | `aet: [eat, tea, ate]; ant: [tan, nat]; abt: [bat]` |

Ответ реализации: `[["eat", "tea", "ate"], ["tan", "nat"], ["bat"]]`.
Он отличается от примера условия только порядком элементов.

## Сложность

Пусть `n` — число слов, `m` — максимальная длина слова, `k` — число групп.

- **Ожидаемое время — O(n · (1 + m log(m + 1))).** Для слова длины `l`
  сортировка занимает O(l log(l + 1)), сборка строки-ключа и вычисление её
  хеша — O(l). Сравнение равных строк-ключей тоже занимает O(l). При обычной
  работе хеш-таблицы число проверяемых ключей в среднем ограничено константой,
  добавление в список амортизированно O(1). Обход всех слов стоит O(n),
  создание внешнего списка ответа — O(k), где `k ≤ n`. При `m ≥ 2` оценку
  обычно записывают как **O(nm log m)**. Единица в полной формуле учитывает
  в том числе пустые слова.
- Это не гарантия времени для худшего случая словаря: при множественных
  коллизиях число сравнений может вырасти до O(n²). Грубая верхняя оценка
  тогда — O(n · (1 + m log(m + 1)) + n² · (m + 1)).
- **Дополнительная память без ответа — O(k · (m + 1) + m + 1).** Словарь
  хранит `k` записей и по одному ключу длины до `m` для каждой группы;
  сортировка очередного слова и временный ключ требуют O(m). Сами исходные
  строки не копируются в группы.
- **Ответ занимает O(n + k)**: `n` ссылок на слова, `k` внутренних списков
  и внешний список из `k` ссылок. С учётом ответа дополнительная память —
  O(n + k · (m + 1) + m + 1), то есть O(n · (m + 1)) для непустого входа.
  Для пустого входа время и память O(1). Рекурсии нет.

## Тесты

Проверяются пример условия, пустой вход и пустые строки, дубликаты, одно
слово, одна и несколько групп, различное число одинаковых букв, Unicode,
регистр, пробелы, сохранность входа и длинные слова. Ещё 200 воспроизводимых
случайных наборов сравниваются с независимым эталоном: ключ из пар
«символ — число вхождений». Сравнение разбиений не зависит от порядка;
отдельный тест проверяет заявленное сохранение порядка.

Запуск из корня репозитория, сторонние библиотеки не нужны:

```bash
python3 -B -m unittest discover -s homework_3/anagrams -v
```
